ABSTRACT
ResumeIntel: An Explainable Resume Intelligence and Skill Gap Analysis Software System
Intended users. People reviewing a resume against a target job description, including resume
owners and advisors. The repository does not establish an employer deployment.
1.1 Problem Background
Resume screening often reduces a resume and a job description to keyword overlap or an opaque score. That can hide whether a
requirement has contextual work evidence, appears only in a skills list, is absent, or cannot be mapped reliably. Noisy extraction can
further complicate review. Reviewers need traceable evidence and uncertainty when comparing stated experience with role
requirements. ResumeIntel addresses this decision-support problem without claiming that textual matches establish competence,
predict hiring, or reproduce an employer’s applicant tracking system.
1.2 Objective of the Project
The objective is to implement a secure, inspectable workflow that extracts resume text, identifies job requirements, links assessments
to source evidence, and summarizes evidence coverage. Reproducible research tools also examine controlled text changes and
compare results with a keyword baseline.
1.3 Proposed Solution / System Overview
ResumeIntel is a web application centered on a deterministic requirement-analysis engine. An authenticated user uploads a PDF or
DOCX; file checks validate type, size, and signature. The user supplies a job description, normalized and parsed into recognized
taxonomy and unresolved bullet requirements. Aliases locate resume evidence and section context. Each requirement receives a
matched, partial, missing, or uncertain state, explanation, and weighted contribution. The application persists a structured report. A
workspace runs baseline, counterfactual, and transformation experiments. Outputs describe evidence coverage; they do not establish
candidate ability or employment outcomes.
1.4 Key Features or Functionality
The report links requirement states to resume excerpts and locations, distinguishes contextual support from skills-list mentions, and
preserves unresolved requirements as uncertain. Required and preferred items receive different weights in a coverage score.
Proficiency estimates cite supporting contexts and state uncertainty. A counterfactual score shows the arithmetic effect of changing
one assessment state. Authenticated history and runs support repeatable review.
1.5 Technology / Method Used
The application uses Next.js, React, TypeScript, Supabase Auth, storage, and PostgreSQL with RLS. PDF.js and Mammoth extract
PDF and DOCX text. An alias taxonomy, deterministic normalization, evidence rules, and weighted arithmetic implement analysis.
Vitest and ESLint verify code.
1.6 Expected Outcome & Benefits
The outcome is a comparison that helps reviewers inspect requirements with support, where it occurs, and items remaining uncertain.
Evidence excerpts and weights make the score auditable. Transformations support research into wording and formatting sensitivity.
The tool cannot verify actual skill, infer protected characteristics, guarantee fairness, or replace judgment. Job-market modules
remain experimental; no validated forecast or model is claimed.
1.7 Original Contribution Statement
ResumeIntel integrates requirement-level evidence, explicit uncertainty, transparent weighted coverage, and bounded counterfactual
explanations in an authenticated workflow with traceable evidence.

Technical description, architecture, methodology, verification and limitations
1. Project background
ResumeIntel is an authenticated web application for evidence-grounded comparison of resume text with a target job description. It is positioned as decision support and reproducible research, not as an
employer ATS, hiring predictor, or verified skills assessment.
2. Problem statement and objectives
Keyword overlap can obscure context: a term listed without work evidence, a requirement not found, or a requirement outside the supported taxonomy can all be treated as equivalent by simpler
systems. ResumeIntel’s objective is to make these distinctions inspectable, provide a transparent weighted coverage calculation, and persist the resulting report for review.

5. Methodology and evidence-based assessment
Job description text is normalized with NFKC and whitespace rules. The parser scans lines for a small explicit alias taxonomy. Recognized terms become requirements; multiword bullet requirements
with no supported alias receive stable unmapped IDs and remain uncertain. Resume text is examined by section-aware lines using complete-term boundaries. No match yields missing; terms in a skills
list or very short excerpt yield partial; contextual occurrences yield matched. Unmapped requirements remain uncertain because the system has no supported skill mapping.

6. Proficiency and counterfactual boundaries
Proficiency is a deterministic heuristic: no useful context gives NOT_ENOUGH_EVIDENCE; skills-list/basic exposure generally gives FOUNDATIONAL; one detailed contextual implementation
gives INTERMEDIATE; two distinct detailed contexts can give ADV ANCED. Confidence labels describe evidence strength and are not statistically calibrated. The output explicitly says this does not
establish competence.
Counterfactual logic changes one requirement state to matched and recomputes the same score. The recommendation is a hypothetical arithmetic impact; it does not prove the person can obtain the skill
or advise a training path.
7. Research and future-skills methodology
The research module includes a token-overlap baseline and transformations that remove a section, reverse section blocks, or replace selected verbs. These transformations are rudimentary; no claim of
semantic paraphrase robustness or validated experimental performance is made. Research run outputs and manuscript revisions are persisted separately.

8. Security and privacy controls
API identity is obtained from the server-side Supabase session rather than a client-supplied owner ID. Resume upload size and signature are checked, storage is private and user-prefixed, database
reads/writes include owner constraints, RLS policies are configured, and the PostgreSQL TLS client sets rejectUnauthorized=true. These are code-level controls; a comprehensive external security
assessment is not claimed.

At documentation preparation, pnpm test passed 49 tests; pnpm lint passed; Python suites covering forecasting and skill-intelligence passed 66 tests. The production build passed with the Webpack

11. Limitations and scope
• The matching engine uses a narrow fixed alias taxonomy and deterministic rules, not a contextual language model.
• Evidence extraction can miss synonyms, nuanced negation, document layout, and requirements expressed outside recognized patterns.
• Score and proficiency labels are heuristics, not calibrated measures, verified skills, hiring outcomes, or fairness guarantees.
• Research transforms do not establish broad semantic robustness.
• Future-skill prediction is experimental, not integrated into operational analysis, and not validated for forecast accuracy.
• No trained adapter is available; AI-assisted labels remain pseudo-labels and must not be treated as ground truth.
12. Conclusion
The strongest supported contribution is an implemented workflow that combines requirement-level evidence, explicit uncertainty, transparent weighted coverage, and bounded what-if scoring within
authenticated, persisted software. The package presents source evidence and limitations so reviewers can evaluate the actual software expression without relying on aspirational claims.

language model.
• Evidence extraction can miss synonyms, nuanced negation, document layout, and requirements
expressed outside recognized patterns.

or fairness guarantees.
